1. SSH Commands SSH

SSH (Secure Shell) lets you run commands on a remote server from your local machine, authenticated with a key pair instead of a password.

Connect to the server

ssh -i ~/.ssh/hetzner_edgeflow root@204.168.198.65
PartMeaning
sshThe SSH client program
-i ~/.ssh/hetzner_edgeflowUse this private key file for authentication (instead of a password)
rootThe user to log in as on the server
204.168.198.65The server's IP address

Run a command remotely (without staying connected)

ssh -i ~/.ssh/hetzner_edgeflow root@204.168.198.65 "cd ~/edgeflow && git stash"

Adding a quoted command at the end runs it on the server and returns the output — no interactive session needed. Use && to chain commands (the next one only runs if the previous succeeded).

2. Git Commands Git

Git tracks code changes locally and syncs them to remote repositories.

Staging and committing

# Stage specific files (mark them for the next commit)
git add file1.txt file2.txt docker-compose.yml

# Commit staged changes with a message
git commit -m "Describe what changed and why"
Working Directory ──► Staging Area ──► Local Repository
    (edit files)       (git add)        (git commit)

Remotes — linking to the server

git remote add hetzner root@204.168.198.65:edgeflow
PartMeaning
hetznerA name you choose for this remote (like a bookmark)
root@204.168.198.65SSH user and server address
:edgeflowPath to the repo on the server (~/edgeflow)

Pushing code to the server

GIT_SSH_COMMAND="ssh -i ~/.ssh/hetzner_edgeflow" git push hetzner master
PartMeaning
GIT_SSH_COMMAND="..."Tells Git which SSH key to use for this push
git pushUpload local commits to a remote
hetznerThe remote to push to
masterThe branch to push
Local (master) ────git push────► Server (master)
   commit A                         commit A
   commit B                         commit B  ← now synced

Server-side Git config

git config receive.denyCurrentBranch updateInstead

By default, Git refuses pushes to a branch that's currently checked out (because the working files wouldn't update). updateInstead tells Git: accept the push AND update the working directory to match — exactly what you want for deployment.

Git stash

git stash

Temporarily shelves uncommitted changes so the working directory is clean. Useful when the server has local edits that would block an incoming push.

3. Docker Commands Docker

Docker runs your app in isolated containers. Docker Compose orchestrates multiple containers together from a single docker-compose.yml file.

docker-compose.yml defines:
┌─────────────────────────────────────────────────────┐
│  Docker Compose Network (internal)                  │
│                                                     │
│  ┌──────────┐    ┌──────────┐    ┌──────────────┐   │
│  │ postgres │    │ backend  │    │   frontend  │   │
│  │ :5432    │◄───┤ :8000    │    │   :3000      │   │
│  │          │    │ (FastAPI)│    │   (React)    │   │
│  │ internal │    └──────────┘    └──────────────┘   │
│  │ only     │                                      │
│  └──────────┘                                       │
└─────────────────────────────────────────────────────┘
        ▲ NOT exposed to internet ✓

Build and start everything

docker compose up -d --build
FlagMeaning
upCreate and start all containers defined in docker-compose.yml
-dDetached mode — run in the background (don't block the terminal)
--buildRebuild images from Dockerfiles before starting (picks up code changes)

Stop everything

# Stop and remove containers (keep data)
docker compose down

# Stop, remove containers, AND delete volumes (wipes DB data)
docker compose down -v
FlagMeaning
downStop and remove all containers. Database volume (your data) is preserved.
-vAlso remove volumes — deletes Postgres data. Needed when changing the DB password, because Postgres only sets the password on first initialization.
Warning: The -v flag destroys all database data. Only use it when you need a fresh database (e.g., password change) or don't have important data.

Verify the security fix Security

ss -tlnp | grep 5432
PartMeaning
ssSocket statistics — shows open network ports
-tTCP sockets only
-lListening (waiting for connections)
-nShow port numbers, not service names
-pShow which process owns the socket
grep 5432Filter for the Postgres port
No output = success — port 5432 is not publicly exposed.

4. Full Deployment Flow

1
Local

Edit your code

2
Local

Stage and commit

git add docker-compose.yml backend/config.py
git commit -m "Describe the change"
3
Local (WSL)

Push to server

GIT_SSH_COMMAND="ssh -i ~/.ssh/hetzner_edgeflow" git push hetzner master
4
Server

Rebuild and restart containers

ssh -i ~/.ssh/hetzner_edgeflow root@204.168.198.65 \
  "cd ~/edgeflow && docker compose down && docker compose up -d --build"
5
Server

Verify

ssh -i ~/.ssh/hetzner_edgeflow root@204.168.198.65 "ss -tlnp | grep 5432"
No output = secure. You're done.
